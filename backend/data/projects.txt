PROJECT: What The Fruit — iOS Application

What The Fruit is a real-time fruit identification iOS app I built entirely within Apple's ecosystem. It is live on the App Store. The app uses the device camera to identify fruits in real time and instantly shows nutritional facts for whatever fruit it detects.

I built it in Swift using SwiftUI for the interface and AVFoundation to capture live camera frames. For machine learning I trained a convolutional neural network on hundreds of thousands of fruit images covering 30 to 50 fruit classes including apple, banana, mango, orange, grapes, watermelon, strawberry, pineapple and more. The model achieved 90 percent accuracy on the validation set. I then converted it from TensorFlow to Core ML format so all inference runs entirely on-device with no network call needed, which means real-time classification at camera frame rate with no latency.

Each frame from the camera is passed through the Core ML model and the prediction result along with a confidence score appears as an overlay on the live feed. When a fruit is identified the app looks up a local nutritional database and displays calories, carbohydrates, protein, fat, fibre, and vitamins per 100g in clean SwiftUI cards. Everything works fully offline once the app is installed.

The app went through Apple's full review process including Core ML model validation, and I optimised the model size for App Store distribution and on-device storage constraints.


PROJECT: Enterprise RAG Assistant — Digital Twin (dwishank.in)

I built a production RAG chatbot deployed at dwishank.in that acts as a digital twin of me. Visitors to the site can chat with an AI that answers questions about my background, skills, and projects as if it were me speaking directly.

The backend is FastAPI running on AWS Lambda via the Mangum adapter, which lets me run an ASGI app serverlessly. The LLM is OpenAI GPT-4o-mini and embeddings use OpenAI text-embedding-3-small. For retrieval I use a hybrid approach that combines BM25 keyword scoring with cosine vector similarity, both normalised and blended with a tunable alpha weight. The top 5 most relevant chunks are injected into the system prompt rather than dumping the full document on every request, which improved answer relevance by around 45 percent over that naive baseline.

The knowledge base is built from my LinkedIn PDF, summary notes, project writeups, and style notes. At startup the corpus is chunked using semantic chunking — splitting on paragraph boundaries, merging short paragraphs, and capping at 300 words per chunk. Each chunk is embedded and stored in memory for retrieval.

For streaming I have a FastAPI endpoint that calls the OpenAI API with streaming enabled and returns Server-Sent Events so the frontend receives tokens as they are generated, giving sub-200ms time to first token. Conversational memory works by storing the last 10 messages per session as JSON in an S3 bucket, loading them on each turn and saving back after each response, which enables full multi-turn context across page refreshes.

All infrastructure — Lambda, API Gateway, S3, and IAM roles — is provisioned with Terraform for reproducible deployments. The frontend is Next.js with TypeScript deployed on Vercel. End-to-end latency is under 2 seconds and the whole system scales to zero when not in use so there is no idle cost.


PROJECT: Real-Time AI Voice Assistant — Hugging Face Space

This is a real-time voice assistant I deployed as a Hugging Face Space. You speak into your microphone, the audio is transcribed by OpenAI Whisper, and then GPT-4o streams back a response token by token. The live demo is at https://huggingface.co/spaces/dwishank/RealTimeAIVoiceAssistant.

I built it with Gradio using the Blocks API. The user records audio via the browser microphone, the audio file is sent to the OpenAI Whisper API for transcription, and the transcript appears immediately in the UI while GPT-4o begins generating. I used Gradio's generator pattern with yield to stream partial tokens back to the interface, so the response box updates live as tokens arrive, similar to how ChatGPT streams responses. Full conversation history is maintained in Gradio State across turns and a reset button clears it for a fresh session.

I kept system prompt responses to 1 to 3 sentences by default and avoided markdown since the output is meant to be read aloud, not rendered. The entire voice-to-text-to-streaming-LLM pipeline runs in under 150 lines of Python with no infrastructure to manage since Hugging Face Spaces handles all the hosting.


PROJECT: Sidekick — Agentic Personal Co-Worker

Sidekick is an agentic AI assistant I built that acts as a personal co-worker capable of autonomously completing multi-step tasks. It runs as a Gradio web app and combines a LangGraph agent loop with a suite of real-world tools, so it can browse the web, write and execute Python code, manage files, search Wikipedia, send emails via SendGrid, and push mobile notifications via Pushover.

The architecture uses a worker-evaluator loop built on LangGraph. The worker node is GPT-4o-mini bound to all available tools and it keeps working on a task — calling tools, reasoning over results, and iterating — until it either has a question for the user or believes it has finished. Once the worker produces a final response, an evaluator node independently judges whether the success criteria provided by the user have actually been met. If they have not, the evaluator feeds back specific criticism and the worker tries again. If the evaluator decides user input is needed — because the task is ambiguous or the agent is stuck — it surfaces that to the user instead of looping indefinitely.

For browser automation I used Playwright via LangChain's PlayWrightBrowserToolkit, which gives the agent a full set of tools to navigate pages, click elements, extract content, and fill forms in a real Chromium browser. The file management toolkit gives it read and write access to a sandboxed local directory. Python execution uses LangChain's PythonREPLTool so the agent can write and run arbitrary code mid-task and use the output to inform its next step.

Conversational memory is handled by LangGraph's MemorySaver checkpointer keyed on a per-session UUID, so the agent maintains full context across multiple turns within a session. The Gradio interface exposes a chat window, a success criteria input, a Go button, and a Reset button that spins up a fresh agent instance and cleans up the browser session cleanly.
